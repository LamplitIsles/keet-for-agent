# Restore conversational Keet reactions through the shared agent boundary

Status: accepted; implemented.

The old DSH bridge offered two conversational reaction behaviors: it supplied aggregate reactions to identity-authored messages as context on a later ordinary trigger, and it could add an emoji to the triggering message after an explicit text send. KFA's current Core can read and add native reactions, but its MCP and webhook boundaries do not expose those behaviors. Restoring them at the shared boundary lets CFL and other webhook consumers receive the same facts without recreating a DSH-specific adapter.

For incoming reactions, KFA will inspect the current reaction state of recent Integration-authored messages in the same Managed Group or DM when a text message qualifies as a trigger. It will attach a bounded snapshot to that text webhook event; a reaction change alone will not create an event or wake an Agent. The snapshot describes the target message and emoji with an external aggregate count, excluding the Integration Identity's own contribution. It carries no reactor identity. The receiver decides which facts fit its next turn, records a durable receipt for each fact actually supplied, and suppresses the same target-message/emoji/external-count tuple on later triggers or webhook retries. A changed external count may be supplied once more. Broadcasts do not have this conversational reaction path.

History identifies candidate messages but its reaction summaries are best effort. KFA uses Core's complete reaction read for each bounded candidate before subtracting its own contribution. An unavailable or invalid complete read omits that target while preserving the text trigger.

For outgoing reactions, the agent's explicit text-send operation may request one Unicode emoji on one specified message in the same Managed Group or DM. Text is required and is sent first. Reaction failure is reported separately and never retries or invalidates confirmed text delivery. A Group target may be a historical message with a known canonical ID. A DM receiver offers only the message that triggered its currently active turn as the reaction target, even if newer DMs are queued; DM history need not expose message IDs for this purpose. KFA validates destination admission and the native target, while the receiver owns the active-turn binding because KFA has no knowledge of an Agent's turn. No standalone reaction send or Broadcast reaction is part of this decision.
